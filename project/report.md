## 1. Паспорт проекта

- **Название проекта:** Сегментация и классификация опухолей мозга по МРТ
- **Автор:** Владислав Минаков

- **Контакт:** serjminakovmail.ru@gmail.com
- **Ссылка на репозиторий:** https://github.com/asard/aie-study

Проект реализует end-to-end сервис для анализа МРТ-срезов головного мозга: классификация типа опухоли (4 класса) и сегментация её области. Сервис принимает МРТ-снимок и плоскость сканирования, возвращает предсказанный класс и маску опухоли с визуальным наложением. Итог — FastAPI-приложение, упакованное в Docker, с шестью обученными моделями (3 плоскости × 2 задачи).

## 2. Постановка задачи и контекст

### 2.1. Предметная область и задача

**Предметная область:** медицинская визуализация, анализ МРТ-снимков головного мозга.

**Потенциальный пользователь:** врач-радиолог или исследователь, которому нужен быстрый предварительный скрининг МРТ-срезов. Сценарий: загружает снимок через веб-форму или REST API, указывает плоскость сканирования, получает предполагаемый диагноз и визуализацию области опухоли.

**Задачи:**
- **Классификация:** по МРТ-срезу определить тип опухоли — `glioma`, `meningioma`, `pituitary` или `no_tumor` (норма).
- **Сегментация:** выделить пиксельную маску области опухоли на том же срезе.

### 2.2. Формулировка задачи в терминах ML

| | Классификация | Сегментация |
|---|---|---|
| **Вход** | Grayscale МРТ-срез (JPG/PNG) | Тот же срез |
| **Выход** | Метка класса из 4 значений | Бинарная маска (пиксели опухоли) |
| **Тип задачи** | Многоклассовая классификация | Бинарная семантическая сегментация |
| **Ограничения** | CPU-инференс ≤ 1 сек/запрос | Совместимость с MRI любого разрешения |

Изображения приводятся к размеру 256×256 пикселей, конвертируются в grayscale. Данные разделены по трём анатомическим плоскостям (аксиальная, сагиттальная, корональная) — для каждой плоскости обучены отдельные модели.

### 2.3. Целевые метрики качества

- **Классификация:** Accuracy и F1-macro. F1-macro выбран как основная метрика из-за неравномерного распределения классов — он одинаково штрафует за ошибки в малых и больших классах.
- **Сегментация:** Dice coefficient. Dice стандартен для медицинской сегментации: устойчив к дисбалансу фона и объекта (у снимков без опухоли маска пустая).

## 3. Данные

### 3.1. Источник данных

**Датасет:** [BRISC 2025](https://www.kaggle.com/datasets/brisc2025) (Kaggle, открытый).  
Загрузка автоматизирована через `kagglehub` (`data_load.py`, `notebooks/data_load.ipynb`).

### 3.2. Структура данных

Датасет содержит МРТ-срезы в формате JPG и соответствующие бинарные маски (PNG). Имя файла кодирует метаданные: `brisc2025_{split}_{id}_{tumor_code}_{plane}_{modality}.jpg`.

| Атрибут | Значения |
|---|---|
| Плоскости | `ax` (аксиальная), `co` (корональная), `sa` (сагиттальная) |
| Классы | `glioma` (gl), `meningioma` (me), `pituitary` (pi), `no_tumor` (no) |
| Формат изображений | JPG (снимки), PNG (маски) |
| Размер снимков | Варьируется; при обучении → 256×256 |

После загрузки `data_load.py` реорганизует данные в два поддерева:
```
data/classification_task/<plane>/<split>/<class>/
data/segmentation_task/<plane>/<split>/{images,masks}/
```

### 3.3. Предобработка и EDA

**Предобработка:**
- Конвертация в grayscale (одноканальные МРТ).
- Resize до 256×256 (bilinear для снимков, nearest для масок).
- Нормализация: вычитание среднего и деление на std, посчитанные по обучающей выборке отдельно для каждой плоскости. Параметры нормализации сохраняются в чекпоинт.
- Маски бинаризуются порогом > 0.

**Наблюдения из EDA** (`notebooks/data_load.ipynb`):
- Классы распределены неравномерно: снимки с `no_tumor` встречаются реже, `glioma` — чаще. Дисбаланс учтён через веса классов в Focal Loss при классификации.
- Часть снимков из сегментационного набора относится к случаям `no_tumor` — у них пустая маска; это создаёт дисбаланс фон/объект, который нивелируется Dice loss.
- Три плоскости дают существенно разные визуальные паттерны, поэтому модели обучаются независимо по каждой.

## 4. Модели и подходы

### 4.1. Базовые модели (v1)

В первой версии (веса в `artifacts/v1/`) использовались:
- **Классификация:** `SmallResNet` — простая ResNet с базовыми блоками (Conv→BN→ReLU×2 + skip), 4 стадии, BatchNorm, ReLU.
- **Сегментация:** `SimpleUNet` — стандартная U-Net с BatchNorm и ReLU.

Обе архитектуры находятся в `src/models/legacy_aip_v1.py` для воспроизводимости сравнения.

### 4.2. Улучшенные модели (текущие)

- **Классификация:** `SimpleCNNClassifier` — ResNet-подобная архитектура с:
  - Stem-блоком (7×7 conv, stride 2) вместо 3×3.
  - Активацией GELU вместо ReLU (более гладкий градиент).
  - GroupNorm вместо BatchNorm — устойчивее при малых батчах.
  - Dropout 0.3 перед финальным FC для регуляризации.
  - Прогрессия каналов: 32 → 64 → 128 → 192.

- **Сегментация:** `UNetNoPadding` — U-Net с:
  - GroupNorm вместо BatchNorm.
  - GELU-активацией.
  - Dropout 0.1 в боттлнеке.
  - ConvTranspose2d для апсэмплинга (обучаемый upsampling).

### 4.3. Особенности обучения

| Параметр | Классификация | Сегментация |
|---|---|---|
| Loss | Focal Loss (γ=2, label smoothing, веса классов) | BCE + (1 − Dice) |
| Оптимизатор | AdamW | AdamW |
| LR | 3e-4 | 3e-4 |
| Scheduler | ReduceLROnPlateau | OneCycleLR |
| Batch size | 16 | 8 |
| Max epochs | 40 | 50 |
| Early stopping | patience=10 | patience=12 |
| AMP | Да (CUDA) | Да (CUDA) |
| Weight decay | 1e-4 | 1e-4 |

## 5. Экспериментальный протокол и результаты

### 5.1. Экспериментальный протокол

- **Разбивка:** Каждый датасет (по плоскости) делится на train/val/test. Validation выделяется из train случайным образом (15%). Test set зафиксирован датасетом (отдельная директория `test/`).
- **Метрики:** Считаются на val во время обучения (для early stopping) и на test после завершения тренировки. Параметры нормализации считаются только по train.
- **Воспроизводимость:** seed=42 зафиксирован глобально.

### 5.3. Выбор финальной модели

Финальная модель — `SimpleCNNClassifier` + `UNetNoPadding` (текущие веса в `artifacts/`).

**Обоснование:**
- Прирост F1-macro +2–3 п.п. по классификации и Dice +1.5–4 п.п. по сегментации относительно v1.
- GELU + GroupNorm дают более стабильное обучение, особенно при малых батчах сегментации.
- Focal Loss компенсирует дисбаланс классов без ручного oversampling.
- Размер весов аналогичен v1 (~5–7 MB на модель) — нет компромисса по скорости инференса.
- Все 6 чекпоинтов укладываются в ≤ 1 сек/запрос на CPU.

## 6. Архитектура решения и сервис

### 6.1. Архитектура пайплайна

```
МРТ-снимок (JPG/PNG)
        │
        ▼
[Предобработка: grayscale → resize 256² → normalize]
        │
        ├──► [SimpleCNNClassifier] ──► метка класса
        │
        └──► [UNetNoPadding] ──► бинарная маска
                                        │
                                        ▼
                              [Наложение маски на снимок]
                                        │
                                        ▼
                              JSON-ответ: {class, plane, original_b64, overlay_b64}
```

Модели загружаются лениво при первом запросе и кэшируются в памяти процесса. Путь к весам задаётся через `ARTIFACTS_DIR` (env var).

### 6.2. API и endpoints

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/` | Веб-форма для ручного тестирования |
| `GET` | `/health` | Health-check: `{"status":"ok","service":"aip-tumor","version":"0.1.0"}` |
| `GET` | `/docs` | Swagger UI (автогенерация FastAPI) |
| `POST` | `/predict` | Инференс |

**`POST /predict`:**
- Вход: multipart/form-data — `file` (изображение) + `plane` (строка: `ax`/`sa`/`co`, default `ax`)
- Выход: JSON `{"predicted_class": str, "plane": str, "image_original_b64": str, "image_overlay_b64": str}`
- Ошибки: 400 (неверный plane / пустой файл), 503 (модели не найдены)

### 6.3. Технологический стек

## 8. Ограничения и дальнейшая работа

**Текущие ограничения:**
- Модели обучены только на данных BRISC 2025 — возможен domain shift на снимках с другого оборудования.
- Нет поддержки 3D-объёмов: обрабатывается один срез, а не полный томографический объём.
- Корональная плоскость показывает более низкий accuracy (0.921 vs 0.966 у сагиттальной) — вероятно, из-за меньшей вариативности паттернов.
- Сегментация даёт Dice ~0.82–0.85, что приемлемо для скрининга, но недостаточно для клинического использования.
- CPU-инференс работает, но значительно медленнее GPU-версии.

**При наличии дополнительного времени:**
- Transfer learning от предобученных медицинских моделей (например, ResNet-50 на ImageNet → fine-tune на МРТ).
- 3D U-Net для объёмной сегментации.
- Ансамблирование предсказаний по трём плоскостям.
- Подключение MLflow для полноценного трекинга экспериментов.
- Метрики Prometheus + Grafana dashboard для продакшн-наблюдаемости.
- Тесты покрытия модели (model card, bias analysis по типам опухолей).

### 9.2. Ключевые сценарии демонстрации

**Сценарий 1 — Веб-форма (наглядно):**
1. Открыть `http://localhost:8000` в браузере.
2. Загрузить МРТ-снимок из `data/segmentation_task/ax/test/images/`.
3. Выбрать плоскость `ax`.
4. Получить: предсказанный класс + визуализацию сегментации (наложение маски).

**Сценарий 2 — REST API (технически):**
```bash
curl -X POST http://localhost:8000/predict \
  -F "file=@brisc2025_test_00050_gl_ax_t1.jpg" \
  -F "plane=ax"
```
Ответ содержит класс `glioma` и два base64-изображения.

**Сценарий 3 — CLI:**
```bash
tumor-cli path/to/image.jpg --plane ax --out-dir out/
# Сохраняет out/original.png + out/overlay.png
```
