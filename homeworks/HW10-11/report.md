## 3. Данные

### 3.1. Часть A: классификация

- **Датасет:** STL10
- **Разделение:** официальный train split (5000 изображений) разбит 80/20 на train (4000) и val (1000) с seed=42; официальный test split (8000 изображений) использован один раз для финальной оценки лучшей модели.
- **Базовый transform (C1):** `ToTensor` + `Normalize(mean=[0.485,0.456,0.406], std=[0.229,0.224,0.225])`
- **Augmentation transform (C2):** `RandomHorizontalFlip(p=0.5)` + `RandomCrop(96, padding=12)` + `ColorJitter(brightness=0.3, contrast=0.3, saturation=0.2)` + `ToTensor` + `Normalize`
- **ResNet transform (C3, C4):** `Resize(128)` + `RandomHorizontalFlip(p=0.5)` + `ToTensor` + `Normalize`
- **Комментарий:** STL10 содержит 10 сбалансированных классов (самолёт, птица, автомобиль и др.) с изображениями 96×96. Датасет относительно небольшой (5000 train), что делает его сложным для обучения с нуля — модели быстро переобучаются. Нативный размер 96×96 сохранён для CNN; для ResNet использован Resize(128) вместо стандартных 224 из-за ограничений VRAM (4.3 GB). Весь датасет переносился на GPU одним тензором до начала обучения, что дало значительное ускорение по сравнению с батчевым DataLoader-подходом.

### 3.2. Часть B: structured vision

- **Датасет:** Pascal VOC 2012
- **Трек:** detection
- **Ground truth:** bounding boxes и метки классов из XML-аннотаций VOC (`xmin, ymin, xmax, ymax` + название класса).
- **Предсказания:** боксы, метки и scores от FasterRCNN_ResNet50_FPN (pretrained COCO); предсказания фильтровались по `score_threshold` и по принадлежности к VOC-классам через маппинг VOC→COCO.
- **Комментарий:** Pascal VOC — стандартный бенчмарк детекции с 20 классами и чёткой XML-разметкой. Использование pretrained COCO-модели оправдано: все 20 классов VOC присутствуют в COCO, поэтому модель способна детектировать их без дообучения. Val split выбран вместо train, так как он меньше и достаточен для демонстрации инференса и метрик.

## 4. Часть A: модели и обучение (C1-C4)

- **C1 (simple-cnn-base):** SimpleCNN (4 блока Conv→BN→ReLU→MaxPool, голова Flatten→Linear(9216,512)→Dropout(0.4)→Linear(512,10)), данные без аугментаций, 2.8M параметров.
- **C2 (simple-cnn-aug):** та же SimpleCNN, данные с аугментациями (RandomHorizontalFlip, RandomCrop, ColorJitter).
- **C3 (resnet18-head-only):** pretrained ResNet18, весь backbone заморожен (11.2M параметров), заменена и обучается только fc-голова (Dropout(0.3) + Linear(512,10)), 5K обучаемых параметров.
- **C4 (resnet18-finetune):** pretrained ResNet18, заморожены layer1-layer3, разморожены layer4 + fc-голова, 8.4M обучаемых параметров.

Дополнительно:

- **Loss:** `CrossEntropyLoss`
- **Optimizer:** `Adam` (для всех экспериментов)
- **Scheduler:** `CosineAnnealingLR(T_max=epochs)` — плавное снижение lr до ~0
- **Batch size:** 128
- **Epochs (макс):** 20
- **Критерий выбора лучшей модели:** максимальный `val_accuracy` по эпохам; best_state сохранялся на CPU при каждом улучшении.

## 5. Часть B: постановка задачи и режимы оценки (V1-V2)

### Если выбран detection track

- **Модель:** `FasterRCNN_ResNet50_FPN` из `torchvision.models.detection`, pretrained на COCO (без дообучения).
- **V1:** `score_threshold = 0.3` — низкий порог, модель выдаёт много предсказаний включая неуверенные.
- **V2:** `score_threshold = 0.7` — высокий порог, только уверенные предсказания.
- **Как считался IoU:** попарная IoU-матрица между pred boxes и GT boxes через векторизованные операции на тензорах; жадный матчинг по убыванию score — каждый GT бокс может быть сопоставлен не более одному предсказанию.
- **Как считались precision / recall:**
  - TP: предсказание сопоставлено с GT при IoU ≥ 0.5
  - FP: предсказание не сопоставлено ни с одним GT
  - FN: GT не сопоставлен ни с одним предсказанием
  - `precision = TP / (TP + FP)`, `recall = TP / (TP + FN)`
  - Метрики агрегированы по всем 100 изображениям val split.

## 7. Анализ

Простая CNN (C1) на STL10 быстро переобучается: при всего 4000 обучающих изображениях модель с 2.8M параметров уже к 20-й эпохе достигает train_acc=0.838 при val_acc=0.655 — разрыв 0.195 говорит о явном overfitting. Датасет слишком мал для обучения глубокой сети с нуля без сильной регуляризации.

Аугментации в C2 заметно снизили переобучение (разрыв сократился до 0.089), подтвердив что RandomCrop и ColorJitter эффективно расширяют эффективный размер обучающей выборки. Однако за 20 эпох C2 не успел сойтись — аугментированные примеры сложнее, и модели требуется больше итераций. При увеличении числа эпох до 40-50 C2 вероятно превзошёл бы C1 по val_acc.

Pretrained ResNet18 в режиме head-only (C3) показал val_acc=0.898 при обучении всего 5130 параметров — это наглядная демонстрация силы transfer learning. Фичи, извлечённые backbone'ом, обученным на ImageNet, оказались универсальными и хорошо описывают объекты STL10 без какой-либо адаптации. Почти нулевой разрыв train-val (0.003) говорит об отсутствии переобучения.

Partial fine-tuning (C4, layer4+fc) добавил +0.021 к val_acc, разморозив 8.4M параметров. Однако train_acc достиг 1.000 уже ко 2-й эпохе — модель буквально запомнила весь train из 4000 примеров. Несмотря на это, test_acc=0.906 показывает хорошее обобщение: pretrained инициализация является сильным регуляризатором, удерживающим модель от полного коллапса в обобщении.

Для детекции выбрана метрика precision/recall при IoU≥0.5 — стандартный порог в задачах детекции, обеспечивающий баланс между точностью локализации и допустимой погрешностью. mean_IoU по совпавшим парам дополнительно показывает качество локализации отдельно от вопроса о количестве предсказаний.

При переходе от V1 (thr=0.3) к V2 (thr=0.7) precision выросла с 0.376 до 0.681 (+0.305), recall упал с 0.904 до 0.803 (-0.101) — классический precision-recall tradeoff. FP сократился с 358 до 90, FN вырос с 23 до 47. Наиболее показательные ошибки V1 — дублирующие боксы на одном объекте и детекция фоновых паттернов как объектов. V2 устраняет большинство таких ошибок, но начинает пропускать частично перекрытые и мелкие объекты.

## 8. Итоговый вывод

В качестве базового конфига классификации я бы выбрал **C4 (ResNet18 finetune, layer4+fc)**: он даёт наилучший test_acc=0.906 и при этом не требует обучения с нуля. Главное про transfer learning: даже head-only режим (C3) даёт колоссальный прирост над обучением с нуля — pretrained фичи универсальны и переносимы между доменами, особенно когда обучающих данных мало (4000 примеров). Разморозка верхних слоёв (C4) даёт дополнительное улучшение, но требует аккуратной регуляризации или раннего останова.

Главное про detection и метрики: не существует единственно правильного порога — выбор между precision и recall определяется прикладной задачей. Для safety-critical приложений важен высокий recall (лучше ложная тревога, чем пропуск объекта), для пользовательских интерфейсов важна высокая precision. mean_IoU показал, что FasterRCNN отлично локализует объекты при любом пороге — узким местом является именно фильтрация по уверенности, а не качество самих боксов.

## 9. Приложение (опционально)

Дополнительно реализовано:

- **Ускорение обучения через GPU-тензоры:** весь датасет переносился на GPU одним вызовом `.to(device)` до начала обучения; батчи нарезались через слайсы `X[i:i+batch_size]` без CPU→GPU копирования в цикле. Это дало ускорение ~100× по сравнению с классическим DataLoader-подходом с поэпохным переносом батчей на GPU. Подход применим пока датасет влезает в VRAM; для больших датасетов рекомендуется DataLoader с `pin_memory=True` и `non_blocking=True`.
- **CosineAnnealingLR:** использован во всех экспериментах части A для плавного снижения learning rate без ручного подбора расписания.
- **Retry-логика при скачивании:** реализована обёртка `load_stl10_to_gpu_safe` с автоматическим повтором при обрыве соединения во время загрузки датасета.
